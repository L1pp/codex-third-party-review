# 后续验证计划（尚未启动）

本轮先完成上下文预算和分层清理；以下三项只准备计划，不发起模型请求，不新增审阅门禁或调用次数硬上限。

## 1. 真实开发问题的审阅收益

优先沿用已准备的 SWE-PRBench 开发 PR 子集，固定同一组题目和参考标注，不临时自编题目，不以 OWASP 代替开发复核。先核实已有输入和结果能复用哪些，答案只供评分。若要补充更长案例，按文件关联和历史长度预先选择，不根据模型结果重新抽题。

对每题分别保存：A 为订阅 GPT 的正常自审；B 为相同外部模型的简单独立调用；C 为完整 Skill（工具探索和上下文管理）的独立审阅。比较 A、A+B、A+C 的发现集合，B/C 不接收 A 的结论。简单调用和完整 Skill 使用同一模型、思考强度及单请求输出配置；材料获取方式是实验变量，分别报告初始和实际读取范围。

主会话核实每条发现，对照人工问题计算“参考问题召回”；不称为完整准确率。人工未标的问题仍可能有效，单独记录新增有效发现、误报、重复与待核实。按用户偏好关注尽量多发现问题，也报告误报，不能用未列入参考答案直接判错。独立评分有分歧时保留各方原记录和主会话裁决。公共题目可能已被训练数据覆盖，小样本不能证明普遍模型排名。

## 2. 同批任务的耗时与用量

复用上面的同批调用，不额外为成本统计重复调用。分开统计：API 请求耗时、完整工作流耗时、主会话验收时间；首事件和首段正文不能混用。逐次记录输入、输出、推理 token、模型/工具调用、分层清理事件和压缩请求，区分本地估算和供应商 usage。

成功和失败耗时分别报告；失败及压缩仍计入整体实际用量。复用台账的详细记录目录，检查断流、缺正文、长度终止和未完成率。比较基线与新版时控制模型、范围和样本，不把一次快速调用归因于上下文机制。Token Plan 额度和按量人民币价格分开计算：先确认实际路由及当日计费规则，再给预算；auto 未返回实际模型时说明成本不确定性。

## 3. 材料与只读边界

优先用离线临时仓库和虚构凭据测试：显式补充文件、被忽略文件、路径/软链接跳转、重叠工作区、staged/range/worktree 版本、删除文件、工具分页、超长行和搜索片段。核对模型实际得到哪些文本，哪些只保存在本地来源记录；单有 source ID 不代表全文已投递。

特别检查：清理标记仍能通过原参数重读；根/版本/行范围不同不能错误去重；保留完整工具往返；原始工具结果、旧请求、各版 checkpoint 均可追溯。日志本身可能含源码，不能凭已知 key 脱敏就认为可公开。不接触真实秘密，不用模型“尝试泄漏”验证边界。

## 开始前需要明确的范围

先向用户报告已有可复用题数、待补调用数、评分方式和按实际账号规则估计的成本，再按授权启动。结果较接近时保留不确定性，若追加题目应预先确定补充集合。当前这份计划不启动正式评测。
